AirPods Mic Bridge 1.3.0 uses active microphone capture instead of an application-specific condition.

- Any active Windows capture session on one unambiguous AirPods microphone can enable the gesture, including voice applications, browser sites and system sessions.
- No process-name lookup, window detection or website allowlist is used. A microphone test can also activate control; this is not detection of a connected call.
- Ambiguous devices, unknown session states and AirPods discovery errors leave control disarmed. Revalidation keeps these checks even when a gesture carries a pinned endpoint ID.
- Transparent microphone-level tray indication, the persistent red 48×48 corner indicator, the optional card, themes and six languages are retained.
- The Windows 11 x64 installer supports six languages, has a compact logo at 100% scaling and creates a brighter Start menu shortcut. Its first dialog defaults to **Current user**; **All users** requires administrator privileges. The following page selects the folder.
- Final **Launch AirPods Mic Bridge** and **Start with Windows** checkboxes are checked by default. `/CURRENTUSER` and `/ALLUSERS` select scope for unattended installation.
- Startup uses a per-user or common Startup shortcut with `--autostart`. The tray can disable startup for the current account without elevation while leaving a common shortcut available to other users. Enabling startup clears the per-user opt-out; elevated `--startup-enable-all-users` and `--startup-disable-all-users` commands manage the common shortcut directly.
- The portable ZIP does not create startup automatically; an existing registration can remain active. Uninstall removes the installation's startup shortcut and retains user settings and diagnostics.
- Tray menus no longer jitter during microphone-level icon updates.
- **Headset diagnostics** adds microphone selection, six prompts five seconds apart, automatic stop after 30 seconds, manual stop and **Save report…** to export JSONL. Open it from the tray or with `--diagnostics`; the wizard supports all six languages and pauses microphone control during the test.
- Light and dark diagnostics themes include the title bar, microphone selector, progress bar and disabled-button text.
- Reports remain local under `%LOCALAPPDATA%\AirPodsMicBridge\diagnostics` and can include Windows media/consumer-telephony HID events, microphone state and audio/Bluetooth/HID driver names, versions and INF identifiers. MagicAAP is included even when registered under another device class. No audio, signal-level history or ordinary keys are recorded. Device names and identifiers may contain a personal headset name or Bluetooth address; reports are not uploaded automatically or attached to releases.

Diagnostics observes commands exposed by Windows, including Play/Pause, Stop and volume. It does not decode private driver traffic or sniff Bluetooth protocol packets. A driver listed in the report is not proof that it emitted an event. Other headsets can be investigated, while microphone control remains AirPods-only.

Mute applies to the Windows recording device and all applications using it. An application or browser site can keep its own mute state. The utility does not enable a disabled browser microphone track. If the application releases its capture session and no other active session remains, resume microphone use in the application before using the gesture again.

The tested hardware delivery setup used AirPods 4 with MagicAAP enabled. This does not claim that every application or Bluetooth driver has been physically tested. Operation without that driver and exclusive-mode/ASIO capture paths remain unverified; exclusive paths can require device hardware mute.

Download and run `AirPodsMicBridge-1.3.0-Setup.exe`, or extract the portable ZIP and run `AirPodsMicBridge.exe`. Default folders are `%LOCALAPPDATA%\Programs\AirPodsMicBridge` for the current user and `%ProgramFiles%\AirPodsMicBridge` for all users. The release also provides English/Russian documentation and SHA-256 checksums. Local checks run with `test.ps1` without recording audio or changing microphone mute. Startup checks use isolated per-user/common-startup directories; installer smoke uses a temporary per-user installation rather than a production all-users deployment.

AirPods Mic Bridge 1.3.0 определяет активное использование микрофона без привязки к конкретному приложению.

- Нажатие работает при активном сеансе записи Windows на одном однозначно выбранном микрофоне AirPods: в голосовом приложении, на сайте в браузере или в системном сеансе.
- Имена процессов, окна и адреса сайтов не проверяются. Проверка микрофона тоже может активировать управление; состояние не доказывает, что идёт звонок.
- Неоднозначность устройства, неизвестное состояние сеанса и ошибки чтения AirPods оставляют управление выключенным. Повторная проверка сохраняет эти ограничения и для указанного в нажатии устройства.
- Сохраняются контурный значок с уровнем сигнала, постоянный красный индикатор 48×48, необязательная карточка, темы и шесть языков.
- Установщик для Windows 11 x64 поддерживает шесть языков, использует компактный логотип при масштабе 100% и создаёт более яркий значок меню «Пуск». В первом диалоге по умолчанию выбрана установка **Для текущего пользователя**; **Для всех пользователей** нужны права администратора. Следующая страница позволяет выбрать папку.
- На последнем шаге флажки **Запустить AirPods Mic Bridge** и **Запускать вместе с Windows** включены по умолчанию. Параметры `/CURRENTUSER` и `/ALLUSERS` задают область установки без мастера.
- Для автозапуска используется личный или общий ярлык с аргументом `--autostart`. Меню трея может отключить автозапуск для текущей учётной записи без повышения прав, сохранив общий ярлык для остальных. Включение удаляет личный маркер отказа; команды `--startup-enable-all-users` и `--startup-disable-all-users` с правами администратора управляют общим ярлыком напрямую.
- Переносной ZIP не создаёт автозапуск автоматически; ранее созданный автозапуск может оставаться включённым. При удалении программы ярлык автозапуска этой установки удаляется, а настройки и диагностические данные сохраняются.
- Меню трея больше не дёргается при обновлении значка уровня микрофона.
- **Диагностика гарнитуры** позволяет выбрать микрофон, выполнить шесть нажатий по подсказкам с интервалом пять секунд и сохранить JSONL через **Сохранить отчёт…**. Проверка завершается через 30 секунд или по кнопке **Остановить**. Мастер доступен в меню трея и через `--diagnostics`, переведён на шесть языков и приостанавливает управление микрофоном во время проверки.
- Светлая и тёмная темы диагностики охватывают заголовок окна, список микрофонов, полосу прогресса и текст отключённых кнопок.
- Отчёты остаются в `%LOCALAPPDATA%\AirPodsMicBridge\diagnostics` и могут содержать медиакоманды и HID-отчёты управления мультимедиа/телефонией, состояние микрофонов, названия, версии и INF-идентификаторы звуковых, Bluetooth и HID драйверов. MagicAAP включается и при регистрации в другом классе устройств. Звук, история уровня сигнала и обычные клавиши не записываются. Названия и идентификаторы могут содержать личное имя гарнитуры или Bluetooth-адрес; автоматической отправки нет, отчёты не прикладываются к релизам.

Диагностика наблюдает команды, которые Windows предоставляет приложениям, включая «Воспроизвести/пауза», «Стоп» и громкость. Она не расшифровывает внутренний обмен закрытого драйвера и не перехватывает пакеты Bluetooth. Драйвер в списке не доказывает, что именно он создал событие. Проверять другие гарнитуры можно; управление микрофоном пока работает для AirPods.

Системный mute влияет на устройство записи и все использующие его приложения. Собственная кнопка mute приложения или сайта может иметь другое состояние; отключённая дорожка микрофона в браузере не включается. Если приложение освободило сеанс записи и других активных сеансов нет, сначала возобновите использование микрофона в приложении.

Проверенная аппаратная конфигурация — AirPods 4 с включённым MagicAAP. Это не означает физическую проверку каждого приложения или Bluetooth-драйвера. Работа без этого драйвера, монопольный режим и ASIO не проверены; такие пути могут требовать аппаратного mute устройства.

Запустите `AirPodsMicBridge-1.3.0-Setup.exe` или распакуйте переносной ZIP и откройте `AirPodsMicBridge.exe`. Папки по умолчанию — `%LOCALAPPDATA%\Programs\AirPodsMicBridge` для текущего пользователя и `%ProgramFiles%\AirPodsMicBridge` для всех. В релизе также доступны документация на русском/английском и контрольные суммы SHA-256. Локальные проверки запускаются через `test.ps1` без записи звука и изменения mute. Проверки автозапуска используют изолированные папки личной и общей автозагрузки; тест установщика выполняет временную установку для текущего пользователя, а не рабочую установку для всех.
