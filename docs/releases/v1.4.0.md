AirPods Mic Bridge 1.4.0 adds short sound notifications when the microphone is muted or unmuted.

- A soft descending chime confirms mute; an ascending chime confirms unmute. The sounds are original synthesized PCM inspired by iPhone/AirPods feedback; no Apple recordings are included.
- **Sound notifications** is on by default, including after upgrading settings from an older version. Turn it off in the tray menu; the preference is saved and available in all six interface languages.
- Sounds follow confirmed bridge toggles and observed external mute changes while one unambiguous AirPods microphone has active Windows capture. Startup, first state detection, reconnection, failed commands, paused control and diagnostics stay silent. A polling refresh does not replay the same change.
- Playback is asynchronous and uses the default Windows playback device at its current volume. Select AirPods as the default output to hear the chime in the headset. Missing playback does not stop microphone control.

This release also includes the application-independent capture selection, Windows 11 x64 installer and headset diagnostics introduced in the 1.3.0 source changes. Voice applications, microphone tests and browser sites use the same active-capture rule; no process, window or website allowlist is required. The dark diagnostics theme includes its title bar, microphone selector, progress track and readable disabled buttons.

Download `AirPodsMicBridge-1.4.0-Setup.exe` for installation, or extract the portable ZIP and run `AirPodsMicBridge.exe`. The installer offers current-user/all-users scope followed by the installation folder, creates Start menu shortcuts, and enables final launch and startup by default. The tray can change startup for the current account. Upgrades preserve settings and the current microphone mute state. English/Russian documentation and SHA-256 checksums accompany the artifacts.

Diagnostics records exposed media/consumer-telephony HID commands, microphone state and bounded driver metadata into a local JSONL report. It pauses bridge control, never records audio and does not upload reports. Other headset brands can be investigated; microphone control remains AirPods-only.

The verified hardware delivery path remains AirPods 4 with MagicAAP enabled. Active-capture selection does not establish compatibility with every application or Bluetooth driver. Operation without that driver and exclusive/ASIO capture paths remain unverified. System mute affects the recording device and all applications using it; an application's own mute button can keep a different state.

`test.ps1` checks generated audio, notification transitions, settings migration, localisation, capture policy, appearance, diagnostics and startup without playback, recording or microphone changes. Installer checks use an isolated current-user installation in each of the six languages.

AirPods Mic Bridge 1.4.0 добавляет короткие звуковые уведомления при включении и выключении микрофона.

- Мягкий нисходящий сигнал подтверждает выключение, восходящий — включение. Звуки синтезированы для утилиты по мотивам уведомлений iPhone/AirPods; записи Apple не включены.
- **Звуковые уведомления** включены по умолчанию, в том числе после обновления прежних настроек. Выключить их можно в меню трея; выбор сохраняется. Пункт переведён на все шесть языков интерфейса.
- Сигнал звучит после подтверждённого переключения утилитой или обнаруженного внешнего изменения mute, пока один однозначно выбранный микрофон AirPods имеет активный сеанс записи Windows. Запуск, первое определение состояния, переподключение, ошибки команд, приостановленное управление и диагностика проходят без звука. Повторный опрос состояния не воспроизводит тот же сигнал снова.
- Воспроизведение асинхронное, через устройство вывода Windows по умолчанию с его текущей громкостью. Выберите AirPods таким устройством, чтобы слышать сигнал в наушниках. Отсутствие воспроизведения не останавливает управление микрофоном.

В релиз также входят выбор активного микрофона без привязки к приложению, установщик для Windows 11 x64 и диагностика гарнитуры из изменений исходников 1.3.0. Голосовые приложения, проверки микрофона и сайты в браузере используют одно правило активного сеанса записи. Имена процессов, окна и сайты не проверяются. Тёмная тема диагностики охватывает заголовок, список микрофонов, прогресс и читаемые отключённые кнопки.

Для установки запустите `AirPodsMicBridge-1.4.0-Setup.exe` либо распакуйте переносной ZIP и откройте `AirPodsMicBridge.exe`. Установщик предлагает область «текущий пользователь/все пользователи», затем папку, создаёт ярлыки меню «Пуск» и по умолчанию включает запуск на последнем шаге и автозапуск. Меню трея меняет автозапуск для текущей учётной записи. Обновление сохраняет настройки и текущее состояние mute. К файлам приложены документация на русском/английском и контрольные суммы SHA-256.

Диагностика сохраняет доступные медиакоманды и HID-отчёты управления мультимедиа/телефонией, состояние микрофона и ограниченные сведения о драйверах в локальный JSONL. Она приостанавливает управление утилитой, не записывает звук и не отправляет отчёты. Можно исследовать гарнитуры других производителей; управление микрофоном пока предназначено для AirPods.

Проверенная аппаратная конфигурация — AirPods 4 с включённым MagicAAP. Определение активного микрофона не означает физическую проверку каждого приложения и Bluetooth-драйвера. Работа без этого драйвера, монопольный режим и ASIO не проверены. Системный mute влияет на устройство записи и все использующие его приложения; собственная кнопка mute приложения может сохранять другое состояние.

`test.ps1` проверяет созданные звуки, переходы уведомлений, миграцию настроек, переводы, выбор микрофона, оформление, диагностику и автозапуск без воспроизведения, записи звука и изменения микрофона. Проверки установщика используют изолированную установку текущего пользователя на каждом из шести языков.
